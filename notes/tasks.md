# Tasks and hooks (`mise-tasks/`)

Every task, its hook slot, and what it does.


| Task | Hook | Does |
|---|---|---|
| `defaults-snapshot` | pre-packages | hashes the defaults domains the UI reads, before bootstrap writes them |
| `brew-bundle` | pre-packages | `brew bundle` over `Brewfile` + `Brewfile.<host>`: installs what is missing, never upgrades (`up` does); a failed entry warns and continues -- re-run `brew bundle` in a terminal. No-op off macOS |
| `luxmini` | pre-packages (gza; skips elsewhere) | installs LuxMini, the front-LED menu-bar app, from the DMG pinned in `mise.mac.toml` `[vars]`: fetch, sha256-verify, stage into `/Applications` -- brew cannot carry it (upstream publishes no tap, and brew 7 refuses path casks); never downgrades an install Sparkle moved ahead, only a bumped pin reinstalls; a failure warns and the bootstrap continues. The LED helper's one-time admin approval belongs to the app's first launch, not here |
| `bootstrap` | the `bootstrap` task slot | for each `dev.mise.*` LaunchAgent: a guarded `launchctl bootstrap` (loads only a not-yet-loaded job) plus a bare `kickstart` (starts a dead agent, no-op on a healthy one -- never kills a running server); then reports who holds each port; also seeds the ha-monitor state tree, since the token copy targets it before the first run. No-op off gza |
| `herdr-plugins` | final | the herdr plugins the keybindings rely on: installs tab-rename, registers the tsk board plugin and installs the tsk agent skill (`tsk setup herdr`, `tsk setup agents --yes`, skipped where tsk is absent), reloads a running server; no-op where herdr is absent |
| `vscode-extensions` | final | the vscodium extensions; no-op where codium is absent |
| `dev-agents` | final (gza; skips elsewhere) | the gza omp sandbox: checks the profile's invariants (herdr socket denied, HERDR control vars stripped, profile by path, root-owned, no `$HOME`/`~/.ssh` grants, personal documents unreachable through default-deny -- no deny rule there, which would outrank the workdir grant, the shared tsk store `$HOME/.tsk` granted to the daily profile and denied to local-omp, `/usr/bin/ssh` denied to the daily profile with the deny lifted in the generated `nwa-omp` profile alone -- invariants 11 and 12), installs the pinned raw binary plus the root:wheel profiles and wrappers (`omp`, `local-omp`, `nwa-omp`) under `/usr/local`, removes the brew omp that would shadow it, seeds the agent's `sign.pub`/`known_hosts` copies and the `local` and `nwa` state trees. `dev-agents check` is the sudo-free static half. The sudo part needs a TTY |
| `system-check` | final | the macOS system settings: FDA-gated app defaults, the Downloads Dock tile (`persistent-others` is outside mise's `dock.apps` and the tile needs `$HOME`, so like Finder's home target the task keeps it), the Bluetooth menu-bar item (volume has no public key -- private per-machine ControlCenter blobs, so it stays manual), hostname, firewall, the tailnet resolvers in resolv.conf, Touch ID, power, updates, the FileVault check, the GPU wired-limit daemon; the desktop also gets Screen Sharing and Remote Login. The sudo part needs a TTY. Dock/Finder/… restart only when a domain they read changed |
| `apple-intelligence` | final | the Apple Intelligence removal via the pinned pared release: disables every feature in its catalog (Siri included), keeps the managed profile installed (one System Settings click per machine), removes downloaded models. Runs only on Apple-silicon macOS 27+ |
| `finder-favorites` | final | Finder sidebar Favorites := exactly the visible `$HOME` directories, alphabetically -- hand-pinned tiles (the stock Applications one included) and stale bookmarks are removed, like the Dock rule. Favorites are an LSSharedFileList archive, not a defaults domain, so the task writes through that (deprecated, alive) API; Finder updates live and a converged list is a no-op. Bookmarks are only ever resolved with no-interaction/no-mount flags and the run has a 90 s watchdog, so a stale item can never block the bootstrap. No-op off macOS |
| `tailscale-ssh` | manual (Macs) | advertise Tailscale SSH on the CLI tailscaled (`tailscale set --ssh`) and report; refuses from a tailnet SSH session (interception would hang it) and while the app variant is installed. Switching variants is a manual sequence |
| `inventory` | manual (Macs) | the diffable manifest of this Mac's app state -- Application Support dirs, sandboxed containers, Group Containers, non-Apple prefs domains, LaunchAgents, the accounts table -- saved to `~/Library/Logs/inventory-<host>.txt`, each line annotated with its owner: `repo` (a dotfiles target or a declarative domain), `brew:<token>` (an installed cask's bundle id or app name), `sync` (a syncthing share), `?` (nobody). The diff of the two Macs' manifests is the transfer backlog; a `?` row on one host alone is untransferred unowned state, and an account row it lacks means sign into it there (credentials stay in the first host's keychain). Sizes print to stdout only, keeping the saved files stable to diff. Refuses inside the omp sandbox, which denies the app-support trees -- run it in a terminal |
| `check` | git hooks + final hook (Macs) | the repo self-test, wired automatic on both ends of every change: the pre-commit/pre-push hooks (`mise-tasks/hooks`; `core.hooksPath` set by the pre-packages hook, so adopting the repo adopts the gate) refuse unchecked trees -- a tree-hash marker lets already-checked ones through silently, `--no-verify` skips the commit and the push gate then catches it -- and the final hook ends every bootstrap with it, where the dot-diff leg is the run's own idempotence assertion. Legs: the config gate (the pre-packages hook's assertion at commit-time), shellcheck over the task scripts, `mise dot diff` emptiness (a non-empty diff is drift -- fail), and the weekly pin-check heartbeat's freshness (a log older than 8 days is a dead agent; nine days of grace after a fresh install), plus the gza-only agent-job heartbeats -- ha-monitor, ha-update, nwa-health: gated on `HOST` (not plist readability, which the omp sandbox denies), both agents loaded, a dated line at most 2 days old, the weekly ha-update at most 8; an install date unreadable in the sandbox reads as unverifiable, never as never-run. The dot-diff leg self-skips inside the omp sandbox, whose profile denies the dotfiles' target paths. A GitHub Actions workflow runs the config gate (one arm per module) and shellcheck server-side on every push and PR -- the backstop where the git hooks are bypassed or missing -- with mise at the `min_version` floor |
| `pin-check` | weekly agent + manual (Macs) | probe the pinned GitHub release URLs -- the omp binary of `dev-agents`, the pared tarball and checksum sidecar of `apple-intelligence`, the LuxMini DMG -- reading the versions from the pin table in `mise.mac.toml` `[vars]` via `mise vars`, so a bump needs no edit here and a missing var fails the check. The `dev.mise.pin-check` agent (`mise.mac.toml`, Wed 09:30) runs it; every run logs one line to `~/Library/Logs/pin-check.log`, whose age `check` reads as the heartbeat's liveness; a broken pin raises a macOS notification and a non-zero exit |
| `ha-monitor` | daily agents + manual (gza) | the Home Assistant health check: an omp run looks for oddities in HA over the API, changing nothing (brief: `agent-jobs/ha-monitor.md`). The work dir is the HA repo (`~/Documents/code/homeassistant`), so omp loads the repo's `AGENTS.md` and `.omp/mcp.json` as context; the generated profile grants the repo read and write to only the notes and the report draft. A TCC denial on `~/Documents` is reported by the preflight as *unreadable*, not *missing*. State (skipped/result/failures, 30 days of run archives) lives in `~/.local/state/agent-jobs/ha-monitor/`; `mise-tasks/_agent-job.sh` holds the harness the three jobs share, and `mise run <job> profile` prints the generated job profile. `dev.mise.ha-monitor` (04:38) runs under `nono run`: only the local model ports and HA at 192.168.0.253 are reachable. `dev.mise.ha-monitor-report` (12:03) posts the outcome to ntfy: nothing when there is nothing to report, one notification on a new failure, one on recovery. Secrets: the repo's `.ha_token` and `~/.local/state/agent-jobs/ntfy_topic`. `HA_MONITOR_DRYRUN=1` prints instead of posting |
| `ha-update` | weekly agents + manual (gza) | the Home Assistant updater: an omp run installs pending HA updates over the API, in order Supervisor, Core, add-ons, custom integrations, firmware, OS, with `backup: true` where supported, release-notes gating, and a stop at the first failure (brief: `agent-jobs/ha-update.md`). Otherwise the ha-monitor pattern (HA repo as read work dir with only the report draft writable), except that this job mutates HA: the network allow-list (HA and the model ports) is the write guard. `dev.mise.ha-update` (Fri 02:33) runs under `nono run`; `dev.mise.ha-update-report` (Fri 06:03) posts the outcome to ntfy. The heartbeat's stale window is 8 days; a weekly job is not dead at 25 h. Same secrets, same `HA_UPDATE_DRYRUN=1` |
| `nwa-health` | daily agents + manual (gza) | the external probe of nwa: an omp run checks nwa from gza over Tailscale SSH, read-only, changing nothing (brief: `agent-jobs/nwa-health.md`). The work dir is the nixos-config flake repo (`~/Documents/code/nixos-config`), with only `health-notes.md` and `report-draft.md` writable; both must stay gitignored in that repo. The sandbox is the nwa-omp shape: `nono wrap` on a profile generated from the installed `nwa-omp` profile. ssh cannot pass a domain allow-list (dev-agents invariant 12), so the filesystem grants are the whole sandbox. The preflight skips with a reason when `nwa:22` does not answer. `dev.mise.nwa-health` (06:13, report 12:03) shares ha-monitor's state machine and 2-day heartbeat window. `mise run nwa-health seed` copies `health-notes.md` from nwa |

They run on every `mise bootstrap` (plain, or with `--update` to refresh
metadata and repositories first — `mise upgrade`, the `up` function, is tool
upgrades, not an apply) and do nothing when
there is nothing to do. The macOS-only tasks carry the `macos` tag and
the gza agent jobs carry `gza` (mise >= 2026.11.2), so a group can be selected
explicitly -- `mise run --tag macos`, `mise tasks ls --tag gza` -- instead
of relying on the uname guards. `--output summary` collapses a multi-task
run to one line per pass; with `task.logs = true` (mise >= 2026.11.3) a
failed task's full output is kept for `mise tasks log NAME`. The
pre-packages hook opens with a config gate:
`mise env` over the loaded config, failing the run when the config does
not parse or contains unknown fields -- normally a typo'd key only warns,
and the slow phases would then run on a half-wrong config.
